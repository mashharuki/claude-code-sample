# 試合後レビュー・改善フレームワーク

SKILL.md のフェーズ4（試合後レビュー）とフェーズ5（Wildcard攻略）で読む。

## 入力テンプレート（ユーザーに聞く/受け取る情報）

すべて揃っていなくてもよい。無い項目は「不明」として進め、無理に埋めない。

```
- 対戦相手: 
- 結果（スコア・勝敗）: 
- 使っていた戦術（システムプロンプトの要約）: 
- 試合中に送ったリアルタイム指示があれば: 
- 得点/失点の時間帯・状況（分かる範囲で）: 
- 気になった場面（ログ・観戦メモ・スクリーンショット等）: 
- スタミナ切れや動きの停滞が見えた場面: 
- 直近の連勝/連敗の流れ: 
- スカウティング・ブロックを入れていた場合、実際の相手の出方と合っていたか: 
- Minds Coach（Animoca Brands）から試合前スカウティングや試合後デブリーフを受け取っていれば、その内容: 
```

Minds Coachのデブリーフを受け取った場合の扱い方は SKILL.md「Minds Coachとの役割分担」を
参照。デブリーフ中の**動かない事実**（スコア・時間帯・使用戦術等）だけを観測事実に転記し、
Minds側の**解釈・因果的な説明**は仮説の材料として扱う（下記の観測事実の基準がそのまま
Minds由来の情報にも適用される）。

## 評価フレームワーク: 観測事実 → 仮説 → 変更案 → 変更しない項目

**観測事実（Observed facts）**
ユーザーが明示的に述べた情報だけを、言い換えの範囲で書く。**新しい事実を1つも作らない** —
「たぶん」「〜のはず」といったヘッジを付けても、ユーザーが言っていない具体的な出来事・数字・
展開（例: 何分に誰から誰へパスが渡って失点した、といった詳細なスコア推移の再構成）を書いた
時点でそれは仮説であり観測事実ではない。ユーザーが「後半30分過ぎから2失点」としか言っていない
なら、観測事実もそこで止める。それ以上知りたい/使いたい情報は「不明」と書くか、仮説の中で
「〜だとすれば」の形で明示的に条件付きの推測として扱う。例（良い書き方）: 「後半30分以降に
2失点、使用戦術はハイプレス」。例（悪い書き方＝観測事実に書いてはいけない）: 「早い段階で
2点リードされたためハイプレスの効果が薄れた」（ユーザーは点差の推移を述べていない）。
出力前に「ここに書いた各文はユーザーの入力に一言一句たどれるか」を自己点検する。

**仮説（Hypothesis）**
観測事実から考えられる原因を1つ以上。複数あってよいが、優先度をつける。例:
「終盤にMFのプレス強度が落ちずスタミナ切れで戻りが遅れた可能性」。
一般的なサッカー論に頼らず、まずこのエンジン・このチームの試合ログで説明できるかを
優先する（前提はSKILL.mdの基本方針1）。

**次戦の変更案（Proposed change）**
仮説に対する打ち手を1つ、小さく出す。「終盤のMFのPRESS_BALL閾値を下げる一文を追加する」
のように、変更範囲が狭く効果を比較しやすい粒度にする。同時に複数の仮説を検証したい場合
でも、変更は1〜2箇所に絞り、残りは次回以降に回す。

**変更しない項目（What stays the same）**
今回の変更で意図せず影響を受けそうな箇所を明示し、「ここは変えていない」と宣言する。
次戦の結果が変更の効果か別要因かを切り分けるための対照点になる。

## 検証指標の決め方

「試合前の戦術調整」フォーマットの検証指標、および次戦後にこのフレームワークへ戻すときの
判断材料は、game_stateから読める・観戦で確認できる指標にする。例:
- 失点数・失点した時間帯の分布
- 特定選手のSHOOT本数/成功率
- スタミナ切れが疑われる場面の発生時刻
- リアルタイム指示に反応した/しなかった回数（分かる範囲で）
- スカウティング・ブロック（`football-tactics.md`5節）の判定条件が実際にどれくらいの
  頻度で発火したか、発火した時の対応が結果に繋がったか

抽象的な「もっと積極的に」ではなく、上記のような数えられる指標に落として次戦の判断材料に
する。相手の傾向読みが外れていた場合は、`football-tactics.md`5節の判定しきい値（例:
「3人以上」「高いvelocity」の基準）を仮説に含めて見直す。

## Wildcard攻略プラン

**重要**: 「Wildcard」という名称の公式ボーナス制度は本スキル作成時点で確認できていない。
最速ゴール・大逆転・格上撃破のような「見せ場」を狙うこと自体は大会の趣旨（ライブ配信・
re:Invent決勝でのステージ披露）と整合するが、正式な採点・認定ルールがあるかは
[agenticfootballcup.ai](https://agenticfootballcup.ai/) や参加ワークショップの最新情報で
必ず確認するようユーザーに伝える。以下は公式制度の有無によらず使える組み立て方。

**狙うWildcard**: 具体的に定義する（例: 「開始1分以内の先制点」「2点ビハインドからの
逆転勝利」「格上との対戦での勝利」）。曖昧な「派手な試合」ではなく判定可能な条件にする。

**推奨戦術**: `football-tactics.md` の戦術一覧から、狙いに直結するものを選ぶ。
- 最速ゴール狙い → ハイプレス＋カウンターアタックの組合せ、FWの初動を早める指示を強化。
- 大逆転狙い → ビハインド時のリスクテイクを通常より早いタイミング（終盤を待たず）で発動。
- 格上撃破狙い → `football-tactics.md`6節「格上相手への挑み方」をベースにする
  （単一戦術に依存しない、相手の弱点を一点で狙う、勝利以外の現実的な着地点も持つ、
  判断をシンプルにして規律で個の力差を埋める）。

**取るリスク**: 通常運用から外れる分、何を犠牲にするかを明示する（例: 「守備の人数を1人
減らすため通常より失点リスクが上がる」）。

**失敗時の代替策**: 早い段階で狙いが崩れた場合に、通常運用（試合を落とさないための戦術）
へ切り替える条件をあらかじめ決めておく（例: 「前半で2失点したら通常のバランス配分に戻す」）。
