# 安全境界とスコープ確認（必読・最初に適用する）

このスキルは「本物の攻撃」ではなく「許可された対象に対する再現可能な検証」を行う。以下のルールは
交渉不可の安全境界であり、レポートの網羅性よりも優先する。

## 対象の確認（監査開始前に必ず行う）

1. 対象がローカルファイルシステム上のリポジトリ / このマシン上で自分が起動したローカルインスタンス
   （`localhost` / `127.0.0.1` / コンテナ内部ホスト名）であることを確認する。
2. 対象が外部ホスト・本番URL・自分の管理下にないエンドポイントを指している場合は、実行を停止し
   ユーザーに「対象の所有者からの許可があるか」を確認する。許可が確認できない外部ターゲットに
   対しては、ネットワーク越しの実攻撃的テスト（リクエスト送信、ブルートフォース、負荷生成）を行わない。
   コード読解・静的解析・依存関係スキャンなど「対象に負荷をかけない調査」は外部リポジトリのクローンに
   対しても実施してよい。
3. どちらか判断がつかない場合は、ユーザーに一度だけ確認する。確認が取れるまで実行系テスト
   （HTTPリクエスト送信、認証試行、負荷生成、fuzzing）には進まない。

## 実行してよいこと

- 対象コードの読解・静的解析（SAST、依存関係脆弱性スキャン、シークレットスキャン、IaC/CI設定の検査）
- ローカルで起動した対象インスタンス（`localhost`、開発用DB、モックの外部依存）に対する:
  - 認証・認可・入力検証・インジェクション・パストラバーサル・HTTP/APIテスト
  - 少量かつ時間を区切った同時実行/競合状態テスト（例: 同一リクエストを10〜50並列で数秒間）
  - レート制限の「回避可能性」検証（実際にサービスを落とすまで送り続けるのではなく、
    制限が機能しているかを数十リクエスト程度で確認する）
  - リプレイ・暗号検証・シリアライズ/デシリアライズの境界値テスト
- 既存テストスイートの実行（unit/integration/regression/build）
- フォールト注入（依存サービスをローカルで落とす・タイムアウトさせる等、対象プロセスに閉じた操作）

## 実行してはいけないこと

- 本番・第三者ホスト・許可のない外部URLに対する実際の攻撃的リクエスト送信
- 対象システムを実際にクラッシュ・ダウンさせることを目的とした無制限の負荷生成
  （メモリ/CPU枯渇テストは「閾値付近まで観測して停止する」PoCレベルに留める。例えば
  「メモリ使用量が上限の80%を超えたら打ち切る」「30秒経過したら打ち切る」といった上限を
  スクリプト側で必ず設ける）
- 発見した認証情報・シークレットを対象システム以外（外部サービス、他人のアカウント等）に対して使用すること
- ソーシャルエンジニアリング、実在の第三者への迷惑行為
- 破壊的操作（`rm -rf`、対象DBのデータ削除、ブランチの強制上書き等）をテストの一部として実行すること。
  データ破壊系の脆弱性を確認する場合は、使い捨てのコピー/コンテナ/ブランチ上でのみ行う

## 実行前チェックリスト（毎回声に出して確認する）

- [ ] 対象はローカル or 自分が管理する使い捨て環境か？
- [ ] 対象データ（DB、ファイル）は破棄してよいコピーか？
- [ ] 負荷・fuzzing・並行テストに時間/回数の上限を設定したか？
- [ ] 発見したシークレットは対象システム外で使用しないと確認したか？

いずれかにチェックが付かない場合は、ユーザーに確認するか、そのテスト区分をレポート上
「未実施（対象外/要許可）」として明記し、理由を書いて次のカテゴリに進む。
